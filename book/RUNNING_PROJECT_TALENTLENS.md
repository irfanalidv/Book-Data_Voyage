# TalentLens — The Running Project

## What we're building

A job market intelligence platform that collects, cleans, analyses, and serves job postings. By the end of the book it has a role classifier, a skill extractor, semantic search, an LLM layer that explains matches, a tool-using agent, a FastAPI service in a slim Docker image, a CI/CD pipeline, and a packaged core library.

**The use case:** a data science student in Bangalore wants to know which skills are in demand, what a Senior ML Engineer really earns compared with an AI Engineer, and which roles are remote. TalentLens is the machinery for answering those questions honestly, including saying when the data can't.

---

## Why this project

Every concept in the book has a home in TalentLens:

- **Data chapters** (4–8): collecting, cleaning, exploring, and testing job-market data
- **Classical ML chapters** (9–12): classify roles, measure which features help, cluster the corpus, and test whether a neural network earns its cost
- **Specialist chapters** (13–15): skill extraction, trends over time, and scaling
- **GenAI chapters** (16–18): semantic search, LLM explanations, and an agent
- **Shipping chapters** (19–22): FastAPI, Docker + Render, CI/CD, a PyPI-ready package
- **Career chapters** (23–24): production case studies and the India playbook

Where a chapter steps outside TalentLens (Chapter 12's teaching datasets, Chapter 14's COVID series), it says why.

## Data

The book runs on a **bundled synthetic corpus**: 576 cleaned postings generated by Chapter 5's demo mode (fictional employers, fixed seed) and cleaned by Chapter 6. It is designed to behave like a real scrape (skewed salaries, overlapping roles, hidden pay), and it reproduces byte for byte from a fresh clone, so every number in the book does too.

For real data:

- **Collect real postings**: `make collect-dataset` with your own Adzuna key in `.env` gathers balanced postings for the five roles, cleans them, and writes `data/clean/jobs_clean.large.csv`, which chapters prefer automatically (`talentlens.paths.jobs_clean_path()`).

Columns after Chapter 6 include `title`, `company`, `city`, `description`, `skills_normalised`, `salary_min`, `salary_max`, `salary_annual_inr`, `salary_disclosed`, `salary_imputed`, `salary_band`, `is_remote`, and `role_category`.

## The `talentlens-core` package (Chapter 22)

```python
from talentlens_core import load_role_classifier, predict_job_role, create_app

pipeline = load_role_classifier()   # Chapter 9's saved model
role, confidence = predict_job_role(
    {"title": "Engineer", "description": "Build RAG pipelines...", "skills_normalised": "Python|LLMs"},
    pipeline,
)
app = create_app()                  # Chapter 19's FastAPI app
```

As written it wraps the chapter modules and needs a checkout of this repository; Chapter 22 explains how to vendor the code for a standalone PyPI release.

## Why this design

Most books use a disposable dataset per chapter. A running project costs more, because every chapter has to fit, but by the end you haven't just learned many things; you've built one real thing, and you've seen its numbers change as each chapter pushes on them.

When you apply for jobs, TalentLens is the portfolio piece. The README is the cover letter. The deployed URL is the demo.
